    WhisperJAV v1.10.0 — Development Change Log¶

    Developer-facing record of what changed on branch v1.10.0 since the 1.9.5 release (8917f5a, tag v1.9.5), why, and how it was checked. It is the source for the 1.10.0 release notes; it is not itself a user text. Ordered by requirement item (docs/requirements/v1.10.x/2026-10-13-release-1.10.0-requirements.md), not by date. Each entry says what the user sees, the commits, the owner's decisions (W-numbers in docs/plans/OWNER_WORDS_V110_CYCLE.md), how it was checked, and what was found and left open. Specs: docs/requirements/v1.10.x/specs/. Both folders are git-ignored.

    State, 2026-10-30 (release): every item in this log is done and committed: items 1, 2a–2f, 3, 4, the accelerators, 12, tuning, 5, 11c, 6, R-NV and the Ensemble defaults; F7 (ChronosJAV's scene records keep the VAD-group times) committed on 2026-10-29 (0568cac, 14af1fa, 606eea8). Installer built on 2026-10-29 from 606eea8: WhisperJAV-1.10.0-Windows-x86_64.exe, 351,195,281 bytes, SHA-256 5000FBC98D93C85D9BC466F2120D16F6B14429C00A022C2C3753B2D28E68CDE1; installed and checked on an NVIDIA PC (evidence D:\WJ110_measure\build_2026-10-29\). After it, two release edits: this paragraph, and the GitHub check automated-execution.yml on Python 3.13 (was 3.12). Nothing pushed; every push on the owner's word.

    State, 2026-10-27: items 1, 2a–2f, 3 and 4 (CrispASR, as the GGUF pipelines) done, and the accelerator redesign (one accelerator per install, owner W234, design section 22 v2 approved W238); branch at f9950dd, 349 commits ahead of main, nothing pushed. No installer has been built since 2026-10-17. The branch has no commits yet for items 12, 5, 10, 11a–c and 6 (their place in 1.10.0 is the owner's decision).

    State, 2026-10-17: items 1, 2a–2f and 3 done; branch at 69c1308, 128 commits ahead of origin/main, nothing pushed. Installer built from 69c1308: WhisperJAV-1.10.0-Windows-x86_64.exe, 350,890,544 bytes, SHA-256 7B87D977F28C64478FC52C4442E976503CF7AA3654003345C15CB9FBA2245CB7. Remaining 1.10.0 work in the owner's order (W91): CrispASR (item 4) → alignment option (12) → XXL as pass 1 (5) → Tools tab (10) → hardening (11a–c) → Chinese GUI (6). Items 7, 8, 9 moved to 1.10.1 (W91).

    Release-wide facts¶

    • Fresh install only. 1.10.0 needs Python 3.13 (requires-python = ">=3.13,<3.14", d8618cb). A 1.9.x install cannot upgrade: 1.9.5's whisperjav-upgrade installs from GitHub main, and pip refuses 1.10.0 on its Python 3.10. There is no 1.9.6 (W26). The release-note sentence telling 1.9 users this is the owner's wording, not yet written.
    • Colab is not supported in 1.10.0 (W42 (3)). The expert notebook keeps installing v1.9.5; it was not changed.
    • Version 1.10.0: installer/VERSION and whisperjav/__version__.py set by the owner (4d890bc, 00a2a62); the 1.9.5 files in installer/generated/ were removed from git (491dd91).

    Item 1 — 1.9.5 baseline and build hygiene (REQ1, N1)¶

    What the user sees. Nothing on screen. The 1.10.0 wheel no longer carries the developer's config backup files: the 1.9.5 wheel held 50 asr_config.backup.*.json files with local program paths.

    Changes. - Config backups (written when BYOP or CrispASR choices are saved in the GUI) go to the user settings folder, %APPDATA%\WhisperJAV\config_backups\ on Windows (~/Library/Application Support/WhisperJAV/… on macOS, ~/.config/WhisperJAV/… on Linux), no longer into the package folder (879c000; test c8b4854). - The wheel names its six config JSON files one by one instead of config/*.json (4eba9ca). - build_release.py stops on uncommitted or untracked files and on any wheel file git does not track; it deletes stale build/ and whisperjav.egg-info/ first, which had carried the backups into a fresh wheel by a second route. --check-tree and --check-wheel <wheel> run the checks alone (9a84a07). - Measurement tools committed (W28, W31: tools in git, documents private): subeval/ (b85fb2d); the 1.9.4 scripts moved to scripts/measure/v1.9.4/ (f2eb87f); call tracer (b44d700); ChronosJAV reference runner options (1b4bf5d); the baseline runner run_f0_baseline.py (4abace4) and summarize_f0.py (1f1360a). docs/measurements/ is no longer tracked; files kept on disk (780f745, 840301f; W30 (2), W40).

    Checked. Baseline: six pipelines (Balanced, Fast, Faster, Fidelity, ChronosJAV Qwen3-ASR, ChronosJAV anime-whisper) on the two reference films, run on the owner's fresh 1.9.5 install D:\195, scored with subeval: D:\WJ110_measure\F0_195\. Build checks H1–H3 passed (spec item 1).

    Item 2a/2b — the new stack: Python 3.13, PyTorch 2.11.0 for CUDA 13 (REQ2)¶

    What the user sees. - The Windows installer brings Python 3.13.16 (00cc4a3) and PyTorch 2.11.0 for CUDA 13.0, which needs NVIDIA driver 580 or newer (4bf02c8, 366c64d, 0321f53, ee1d444). - Older cards stop before anything is installed. A card below compute capability 7.5 (GTX 900/1000 series, V100) gets the owner's warning and three typed choices: 1 = card identified wrongly (issues link, then stop), 2 = install for the CPU only, 3 = stop (with the 1.9.5 download link). No time limit on the answer (W36 (1), W37, W43). - An older driver stops with the owner's text naming the driver version and the 580 floor, before PyTorch is installed. In 1.9.5 such a PC silently got the CPU build (W36 (2)). - Balanced, Fast and Faster keep the GPU on the CUDA 13 install: the installer places NVIDIA's CUDA 12 cuBLAS (nvidia-cublas-cu12 12.8.4.1) in the ctranslate2 folder, because CTranslate2 still needs cublas64_12.dll (a528d23). If this PC cannot load that file, the installer shows a framed warning that waits for Enter and installs the CUDA 12.8 build instead (W37 (3), W42 (4)). The build used is written to whisperjav_stack.txt; whisperjav --check prints one line on a CUDA 12.8 PC and names missing cuBLAS files (df0a44f, a3e5f9e). - The start-up message for an unsupported card now says 1.10 does not support it and 1.9.5 does, with the link. - Linux stays on CUDA 12.8 in 1.10.0, driver floor 570 (W45): on Linux pip-installed cuBLAS 12 is found only with LD_LIBRARY_PATH set before Python starts. Not tested on a Linux PC. - Source installers (install.py, Linux, macOS and Windows scripts) ask for Python 3.13 (babbab0, 544502e, c348b6e, ca8edd9).

    Versions. numpy 2.5.x (W44; the upper bound follows numba). On Python 3.13 several packages move a major step from 1.9.5: librosa 0.11 → 1.0.0, pandas 2.3 → 3.0, av 17 → 19, scipy 1.15 → 1.18, scikit-learn 1.7 → 1.9, onnxruntime 1.23 → 1.31 (later 1.29.0 in the lock). Every librosa call WhisperJAV makes was run on 1.0.0.

    Checked. S1 (WJ110 on the stack), S2–S4 (fresh install, clean-environment run, forced cuBLAS failure → CUDA 12.8): the owner, "All S1 - S4 passed" (W63). S5 (card and driver decisions with fake nvidia-smi output) in tests e60fc47. One assessment-adversary review (2026-10-14): a failed cuBLAS download now stops the install instead of moving to CUDA 12.8; the fallback replaces only the PyTorch packages; test switches WHISPERJAV_TEST_FORCE_COMPUTE_CAP, WHISPERJAV_TEST_FORCE_DRIVER, WHISPERJAV_TEST_FORCE_CUBLAS12_FAIL.

    Item 4 — CrispASR: the GGUF pipelines Parakeet-CrispASR and Cohere-CrispASR (owner W118, W176 route B)¶

    What the user sees. - Two Ensemble pass pipelines for Japanese, under GGUF in the Pass 1 / Pass 2 menus: Parakeet-CrispASR (parakeet-tdt-0.6b-ja, 674 MB) and Cohere-CrispASR (cohere-asr-ja-v0.1 by default, or cohere-asr-ja, 2,424 MB each). (Cohere-CrispASR's line rule changed in item 12: aligned, cut at sentence ends.) - CrispASR comes with WhisperJAV as a Python package (crispasr 0.8.44), in the build of the install's accelerator: the CUDA build (NVIDIA), the Vulkan build (GPU through Vulkan and Own PyTorch on Windows), the macOS build (Apple GPU), the CPU build otherwise. WhisperJAV downloads the model on first use, pinned by commit and SHA-256 (crispasr/manifest.py). - Parakeet-CrispASR cuts subtitles only at natural cues — sentence-end marks, a pause of 0.6 s, or 、/space followed by 0.4 s — never by characters or duration, with times from the model's tokens (W203, W204). Cohere-CrispASR makes one subtitle per VAD group. Parakeet uses fidelity's speech segmenter settings with 6 s groups, Cohere the qwen pipeline's (W199 DIR1, W202). Both print the audio analytics with semantic scenes (W211 C2). - The pass's scene detector (semantic, 12–48 s, by default), speech enhancer, Enhance for VAD only and Customize (Segmenter, Enhancer, Scene tabs) work as for the other passes (W212 D3, W214 2, W232 8). With an enhancer, the model is opened per file and closed after it, so the two never hold GPU memory together (W217 19). - A status panel under a GGUF pass: the model (downloaded or not) and where CrispASR runs. whisperjav --check lists CrispASR's version, build and device and the three models. - The folder-name note (T24, agreed wording, D-H): "The GGUF (CrispASR) pipelines need folder names in plain Western letters (ASCII). When your user folder has Chinese, Japanese or Korean characters, WhisperJAV links or copies the model to a plain-named folder (the original stays where it is)." The clause about installing WhisperJAV itself in such a folder was dropped after the check of plan step 3 (CrispASR loads and transcribes from a folder with Japanese characters). - The 1.9.x bring-your-own CrispASR mode is removed: --mode crispasr, the pass value crispasr, --crispasr-exe, --crispasr-backend, --crispasr-args stop with exit 2 and a message naming the new pipelines (W118 3).

    Checked.     The accelerators — one accelerator per install (owner W212 D1, W217, W232–W234; design section 22 v2, W238)¶

    What the user sees. - Every install is made for one accelerator, chosen once at install and recorded in whisperjav_stack.txt: NVIDIA GPU (CUDA), GPU through Vulkan (AMD, Intel or older NVIDIA card; Windows), Apple GPU (Metal), Own PyTorch, CPU only (not accelerated). Every run and whisperjav-upgrade follow the record; a second run of an installer offers it as the default. - No run-time question any more. The GUI box "Accept CPU-only mode" is removed; --accept-cpu-mode, --hf-device and --qwen-device are still accepted but hidden (the last two as names for --device). --device auto|cuda|cpu governs every pipeline, the speech enhancers included; --device cpu is absolute. - At the start of a run: an NVIDIA install whose GPU is usable is silent; one whose GPU cannot be used now is the one stop (exit 3; the GUI offers "Run on the CPU this time"); every other install shows a box of where each part runs and goes on. PyTorch missing or damaged: exit 4 with the command that fixes it. The GUI shows "The run did not start" (exit 2, 4) and "The run ended without a run summary" instead of "Finished with failures". - Windows installer: with no supported NVIDIA GPU, a window asks what the install is made for (CPU only after 20 s without an answer; Stop pre-selected with no time limit when an NVIDIA GPU 1.10 cannot use is found, with the reason first). Own PyTorch installs everything except PyTorch and shows the one command to add it (also saved in OWN_PYTORCH_NEXT_STEP.txt). - Source installs: install.py --accelerator nvidia|vulkan|own-pytorch|cpu; without it, a supported NVIDIA GPU or an Apple silicon Mac is chosen by itself, otherwise the same question in the console. --cpu-only, --cuda, --force-cuda still work (hidden). A chosen Stop exits 0 (W241 Q3). - Unsupported computers are refused before anything is installed, in the owner's form: Windows on ARM and before Windows 10; Linux with glibc below 2.35; Intel Macs and macOS before 14; Python under Rosetta; Colab and Kaggle (W233 R6, D-F). - balanced, fast and faster use the GPU only when CTranslate2 itself sees an NVIDIA GPU (a ROCm PyTorch no longer sends them to a GPU they cannot use). On an Apple silicon Mac each pipeline says where it runs (T51–T53). - Lock: a fourth extra vulkan; CrispASR on every platform of each extra (PyPI CPU builds, the +cuda and +vulkan wheels by URL and SHA-256). Only two packages were added to uv.lock (253 → 255); no other version changed.

    Checked. Plan step 3 P8 (D:\WJ110_measure\step3_2026-10-27\): WJ110 runs above; a CPU-only source install into a scratch environment (exit 0, record cpu, --check exit 0); the Vulkan load check; the Japanese install folder. One assessment-adversary review of P2–P6, 17 findings, each checked; fixed with tests or answered (decision record §14.12); 20 test files after the fixes, all passed (p7_fix_tests.log). Not checked: any AMD or Intel GPU; a real Own PyTorch install over another torch; the Windows installer window in a real install (plan step 5); anything on a Mac or a Linux PC.
